# DEC-019 유효 견적 요청 기준

- 상태: **부분 합의**
- 결정일: 2026-08-05
- 참여자: 캐리, 스마일, 밀란, 타스, 코코

## 결정

- 현재 MVP 지표에서는 필수 형식 검증을 통과한 고유 제출을 유효 견적 요청으로 집계한다.
- 명백히 잘못된 연락처 등 형식 오류는 저장·집계하지 않는다.
- 정보 부족이나 운송 불가 요청도 형식 검증을 통과했다면 사용자 수요로 별도 사유와 함께 기록한다.

## 검토한 선택지

- 필수 형식을 통과한 제출 기준
- 운영자가 의도를 확인한 요청 기준
- 제출 수와 운영 확인 유효 수를 나누는 2단계 지표

## 미완료 부분

“같은 사용자·같은 물품 종류”만으로 중복을 확정하면 서로 다른 거래를 지울 수 있다. 중복 키, 재시도 멱등성, 운영자 판정과 스팸 기준은 실제 제출 패턴을 본 뒤 보완한다.

## 영향·검증

- 담당: 캐리
- 기한: 첫 사용자 실험 분석 전
- 막히는 작업: 정확한 실험 지표와 중복 제거 분석
- 개발 차단: 공통 환경과 첫 저장 기능은 차단하지 않음
- 사용자 공개 차단: 아님. 단, 중복 처리 안내와 안전한 재시도는 기능 구현 시 필요
- 재검토: 첫 5건 또는 중복 의심 사례 발생 시

## 연결·영향

- 관련 문서: `docs/product/product-brief.md`, `mvp-scope.md`, `glossary.md`
- 관련 카드: 다음 Sprint 저장·중복 처리, 실험 분석 카드
- 사용자 영향: 재시도를 스팸으로 오인하지 않아야 함
- 운영 영향: 정보 부족·불가·중복 사유 기록
- 기술 영향: 안전한 재시도와 원본 보존이 필요
- 대체: 없음
