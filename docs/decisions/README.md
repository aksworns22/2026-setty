# 결정 기록 운영 방법

## 목적

회의에서 정한 내용이 대화 속에만 남거나, 나중에 왜 그렇게 정했는지 알 수 없게 되는 것을 방지합니다.

## 파일 규칙

- 결정 번호: `DEC-001`, `DEC-002` 순서
- 파일명: `DEC-001-short-title.md`
- 전체 현황: [`DECISION-LOG.md`](DECISION-LOG.md)
- 새 기록: [`TEMPLATE.md`](TEMPLATE.md)를 복사해 작성

## 상태

- `제안`: 선택지를 검토 중
- `합의`: 5명이 동의해 현재 적용 중
- `부분 합의`: 방향은 정했지만 구현·운영의 일부 조건이 남음
- `검증 필요`: 외부 근거 또는 실제 환경 확인 전 적용 범위가 제한됨
- `담당자 지정 필요`: 역할 구조는 정했지만 실제 이름이 없음
- `대체됨`: 새로운 결정으로 교체됨
- `보류`: 위험 또는 정보 부족 때문에 아직 적용하지 않음

## 합의 규칙

- 5인 합의를 기본으로 한다.
- 합의하지 못한 가역적 사안은 가장 작은 실험으로 검증한다.
- 개인정보·법률·외부 비용·실제 사용자 피해 가능성이 있는 사안은 합의 전까지 보류한다.
- 반대 의견은 삭제하지 않고 결정 이유에 함께 남긴다.
- `검증 필요`에는 담당자·기한·방법·막히는 작업·개발 차단·사용자 공개 차단을 적는다.

## 코드·문서와 연결

- Issue에는 관련 결정 번호를 적는다.
- 결정 때문에 요구사항이 바뀌면 같은 PR에서 최신 문서를 수정한다.
- 결정이 바뀌면 과거 기록을 편집해 지우지 않고 새 기록에서 대체 관계를 남긴다.
