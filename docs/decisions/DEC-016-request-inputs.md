# DEC-016 예상 견적과 배차 요청 입력

- 상태: **합의**
- 결정일: 2026-08-05
- 참여자: 캐리, 스마일, 밀란, 타스, 코코
- 관련: 제품 흐름·MVP 범위, 다음 기능 Sprint의 견적·배송 카드

## 문제와 사실

예상 견적과 실제 배차 요청 단계에서 무엇을 받을지, 두 흐름을 어떻게 연결할지 정해야 했다. 견적만 받고 종료하거나 견적 없이 바로 배차 요청할 수 있으며 운송 판단은 운영자가 한다.

## 선택지

- 최소 입력 후 운영자 보완
- 판단 정보 전부 필수
- 단계형 입력과 별도 배차 요청

## 결정

- 예상 견적 필수: 이름, 연락처, 거래 지역, 물품 종류, 50만 원 초과 여부
- 예상 견적 선택: 사진
- 배차 요청 구매자 필수: 이름, 연락처, 수령 상세주소, 물품 종류, 사진, 50만 원 초과 여부
- 판매자 필수: 이름, 연락처, 발송 상세주소, 발송 가능 시간
- 예상 견적은 운영자의 문자 안내에서 종료된다.
- 문자 링크의 `견적 신청하기` 또는 홈의 `배차 요청하기`는 새로운 배차 요청을 만든다.
- 사용자는 실제 거래 내용을 다시 입력하며 예상 견적 값을 자동 복사하지 않는다.

## 이유와 영향

거래 전 낮은 제출 부담과 실제 배차에 필요한 정확한 정보를 분리한다. API·DB도 예상 견적과 배차 요청을 서로 다른 수명주기로 다뤄야 한다.

## 우려·검증·재검토

- 개인정보 동의는 DEC-020 완료 전 실제 접수에 사용할 수 없다.
- `견적 신청하기` 명칭 혼동 여부를 공개 전 확인한다.
- 사진 크기·저장은 DEC-023에서 검증한다.
- 전환 단계 이탈이 높으면 입력 재사용을 다시 검토한다.

- 검증 담당: 코코(입력 흐름), 밀란(개인정보·사진)
- 개발 차단: 공통 환경과 가상 데이터 기반 입력 개발은 차단하지 않음
- 사용자 공개 차단: 개인정보 동의와 사진 정책 미확정 시 해당 입력 공개 차단
