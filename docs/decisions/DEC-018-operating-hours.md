# DEC-018 접수·운영시간과 회신 목표

- 상태: **합의·측정 필요**
- 결정일: 2026-08-05
- 참여자: 캐리, 스마일, 밀란, 타스, 코코

## 결정

- 폼은 24시간 접수한다.
- 운영시간은 주말 포함 10:00~20:00다.
- 운영시간 밖 요청은 다음 운영 시작 후 처리한다.
- 운영시간 내 5분 회신을 내부 목표로 측정하되 사용자에게 보장하지 않는다.
- 첫 MVP에는 동시 처리 한도를 두지 않는다.
- 지연 문구 초안 책임자는 캐리다.

## 검토한 선택지

- 24시간 접수 후 다음 운영시간 처리
- 운영시간에만 접수
- 24시간 접수하되 대기 한도 초과 시 중단

## 이유·우려

수요 데이터를 잃지 않으면서 수동 운영 기대를 관리한다. 5분은 리허설로 검증되지 않았고 무제한 접수는 운영 과부하를 만들 수 있다.

## 검증

- 담당: 캐리
- 기한: 폼 공개 전
- 방법: 가상 요청 리허설과 초기 실요청의 접수~문자 발송 시간 기록
- 개발 차단: 공통 환경과 가상 데이터 기능 개발 차단 없음
- 사용자 공개 차단: 운영시간 밖·지연 문구가 없으면 폼 공개 차단
- 재검토: 5분 목표 미달 또는 대기 요청 누적 시

## 연결·영향

- 관련 문서: `docs/product/product-brief.md`, `user-operation-flow.md`, `mvp-scope.md`
- 관련 카드: 다음 Sprint 접수 결과·운영 대기 문구
- 사용자 영향: 언제 처리되는지 명확히 봐야 함
- 운영 영향: 야간 접수와 지연을 수동 관리
- 기술 영향: 접수는 막지 않고 운영시간 안내를 표시
- 대체: 없음
