- 상태: **워크북 반영본·팀 대조 검토 필요**

## 1. 한 문장 정의

**[팀 확정]** SETTY는 중고 가구·가전 거래 당사자 대신 운송 가능 여부와 비용을 확인하고, 구매자·판매자의 배송 정보를 분리해 받아 실제 운송을 조율하는 무상 중개 서비스다.

SETTY는 중고 매물을 등록하거나 판매하는 거래 플랫폼이 아니다. 향후 범위 확장은 별도 법률·사업 검토와 새 결정 기록이 있을 때만 검토한다.

## 2. 해결하려는 문제

- 구매자는 거래 전에 물품이 퀵·화물 운송으로 가능한지, 비용이 어느 정도인지 판단하기 어렵다.
- 접수 가능 여부와 적절한 차량은 현실적인 운송 경험이 있는 사람이 요청별로 판단해야 한다.
- 실제 거래 단계에서 구매자와 판매자는 상세주소를 상대방에게 직접 알려주는 것을 불편해할 수 있다.
- 가격 확인, 판매자 정보 취합, 배차와 실패 대응이 여러 채널에 흩어져 있다.

SETTY는 운영자가 운송 가능 여부를 판별하고 양쪽 정보를 중개함으로써 사용자의 판단 부담과 당사자 간 상세 위치 노출을 줄인다.

## 3. 초기 대상

**[팀 확정]** 주요 사용자는 에브리타임을 이용하는 서울권 학교 주변 사용자다. 광고에서는 중소형 가구·가전을 중심으로 설명하지만, 폼에서 물품 종류를 과도하게 제한하지 않는다. 실제 접수 가능 여부는 운영자가 요청별로 판단하고 불가능하면 그 사실을 직접 안내한다.

**[팀 확인 필요]** 처음 운영할 학교·지역 목록과 서울권 밖 요청의 안내 문구는 공개 전 확정한다.

## 4. 제공 가치

- 거래 전 간단한 정보로 예상 운송 가능 여부와 예상 금액을 물어볼 수 있다.
- 견적만 확인하고 거래나 배차 요청 없이 정상 종료할 수 있다.
- 실제 거래를 진행할 때 구매자와 판매자가 상세주소를 서로 직접 볼 필요를 줄인다.
- 운송 경험이 있는 운영자가 물품·현장 조건에 맞는 차량과 접수 가능 여부를 판단한다.
- 구매자 동의 후 운영자가 외부 운송 채널에서 착불 배차를 조율한다.

## 5. 두 요청의 구분

### 예상 견적 요청

**[팀 확정]** 거래 전 대략적인 가능 여부와 비용을 묻는 간단한 요청이다. 사용자는 이름, 연락처, 거래 지역, 물품 종류, 50만 원 초과 여부를 입력하고 사진은 선택해서 제출한다. 운영자가 직접 검토·가격 조회 후 문자로 응답한다.

예상 견적은 참고 정보이며 실제 주소와 시간으로 산정한 최종 금액을 보장하지 않는다. 문자 응답을 받은 뒤 아무 행동 없이 종료하는 것도 정상 결과다.

### 배차 요청

**[팀 확정]** 실제 거래를 진행하기 위해 구매자·판매자의 상세 배송 조건을 새로 수집하고 SETTY 운영자에게 수동 배차 조율을 요청하는 별도 흐름이다. 다음 두 경로로 시작할 수 있다.

1. 예상 견적 응답 문자에 있는 `견적 신청하기` 링크로 진입
2. 홈에서 `배차 요청하기`로 진입

문자 링크로 들어오더라도 예상 견적 입력값을 자동으로 이어받지 않는다. 사용자는 실제 거래 내용을 다시 입력하고 새로운 배차 요청을 만든다. 분석을 위해 원본 예상 견적과의 연결 식별자만 저장할 수 있다.

**[팀 확인 필요]** 예상 견적 문자 링크의 `견적 신청하기`와 홈의 `배차 요청하기`를 같은 배차 요청 화면으로 연결할지, 사용자 문구를 하나로 통일할지 공개 전 확인한다.

| 회신 목표 | **[팀 확정]** 운영시간 내 5분을 내부 운영 목표로 측정. 사용자 보장 문구로 사용하지 않음 |

| 운송비 | **[팀 확정]** 구매자가 기사 또는 운송자에게 착불로 직접 지급 |

| 운영 책임 | **[팀 확인 필요]** 운영 주담당과 백업의 실제 이름은 Sprint 배정 시 입력 |

## 7. 첫 MVP에서 사람이 하는 일

- 운송 가능·불가능 판단
- 차량 종류 판단
- 외부 운송 채널에서 예상·최종 가격 조회
- 예상 견적과 최종 금액 문자 발송
- 판매자 입력 독려
- 외부 운송 채널에서 착불 배차
- 기사 미배정, 취소, 지연, 배송 문제 대응
- 배송 완료 확인과 사용자 인터뷰

시스템은 위 작업을 자동으로 수행하지 않는다. 요청·입력·상태와 운영 결과를 저장하고 운영자가 수동 업무를 빠뜨리지 않도록 돕는다.

## 8. 첫 MVP 검증 목표

**[팀 확정]** 첫 공개 실험의 최소 목표는 유효 예상 견적 요청 5건과 실제 배송 완료 1건이다. 초기 목표일은 2026-08-13이며 일정은 실제 준비 상황에 따라 재확인한다.

기록할 데이터:

- 제출된 예상 견적 요청 수
- 운송 가능·불가능 수와 사유
- 문자 안내 후 종료한 수
- 문자 링크 또는 홈의 배차 요청으로 유입된 수
- 배차 요청 단계별 이탈과 완료 수
- 요청별 수동 운영 소요 시간과 예외

**[팀 확정]** 현재 유효 요청은 필수 형식을 통과한 고유 제출로 집계한다. 같은 사용자·같은 물품 종류만으로 중복을 확정하기에는 기준이 부족하므로 실제 데이터 확인 후 보완한다.
